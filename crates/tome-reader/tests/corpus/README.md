# 排版合成语料

`tome-reader` 各切片验收的载体（tasks.md 002 T004 起）。与 001 的
`tests/corpus/`（`tome_rule::corpus`）同构，但**期望值的形态不同**——见下。

## 为什么是"合成"的

真实书源的正文对照数据是第三方资产，不入仓库（`AGENTS.md` 的 gitignore 约定、
宪法原则 II）。故入仓库的是**合成用例**：输入 → 期望，全部可复现、可审查、
可追溯到公开依据（UAX#14 / CLreq / MASTER.md）。

## 文件格式

每个 `.json` 文件是一个用例数组。**全部字段必填**——不用 `#[serde(default)]`
兜底：一条只写了输入忘了期望的用例，默认值会让它"通过"（空期望 == 空实际），
从而伪装成有效覆盖。

```json
[
  {
    "name": "kinsoku:闭标点不得置于行首",
    "input": {
      "kind": "text",
      "paragraphs": ["第一段", "第二段"]
    },
    "geometry": {
      "measure_px": 342.0,
      "font_size_px": 19.0,
      "line_height": 1.85,
      "paragraph_indent_em": 2.0
    },
    "expect": {
      "kind": "kinsoku",
      "forbidden_at_line_start": ["，", "。"],
      "forbidden_at_line_end": ["（", "「"]
    },
    "basis": "UAX#14 LineBreak.txt 18.0.0 的 CL 类不得置于行首；……"
  }
]
```

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 唯一标识。**必须**带冒号前缀（`kinsoku:` / `squeeze:` / `mixed:` / `line_breaks:` / `kinsoku_exceptions:`）——分类统计按前缀分组，无前缀的用例会掉进 `other` 而不被注意 |
| `input` | 是 | `{"kind": "text", "paragraphs": [...]}`。段内换行由 S2-1 的段落切分（FR-001）处理，本字段**不预先切段** |
| `geometry` | 是 | 几何参数四件：版心宽（px）/ 字号（px）/ 行高（倍数）/ 段首缩进（em，0 = 段间距模式） |
| `expect` | 是 | 期望，见下 |
| `basis` | 是 | **期望值的依据**（非空字符串，见下） |

## `expect` 的五种形态

| `kind` | 断言什么 | 服务于 |
|---|---|---|
| `kinsoku` | 行首/行尾**不得出现**的字符集 | SC-001 / SC-002 |
| `kinsoku_exceptions` | 硬序第 ④ 步（放弃禁则）的例外条数与规则标识 | FR-008 / SC-002 |
| `squeeze` | 逐行的压缩量（px） | FR-006 / SC-003 |
| `mixed_script` | 逐行是否超宽 | FR-009 / SC-003 |
| `line_breaks` | 逐行的字符数 | 断点正确性 |

## 为什么期望值是**结构**而非字符串列表

001 的语料期望是"字符串列表"，因为规则求值的输出就是字符串序列。排版不是：
它的输出天然是结构化的（行盒、字符区间、例外记录）。把结构压成字符串再比对，
会丢掉"错在哪一位"的定位能力——一个 300 字的段落，行数对不上时报"整体不等"
远不如报"第 3 行应为 18 字、实为 17 字"有用。

## `geometry` 为什么不含呈现参数

颜色、主题、字体族**刻意不在** `geometry` 里：FR-019 要求呈现参数不得影响分页。
让它们出现在语料中会诱导出"主题相关的期望值"，与「主题切换不重排」这条
不变量直接冲突。几何与呈现的分离在语料格式上就该可见。

## `basis` 是硬性要求

与 001 同理由，但依据来源不同：

- **排版规则** → 公开规范：`UAX#14 LineBreak.txt`（Unicode 换行属性）、
  `CLreq`（W3C 中文排版需求）、`CSS Text` 等
- **设计参数** → `design-system/MASTER.md`（用户拍板的唯一设计规范）
- **项目裁决** → `specs/002-typesetting-renderer/OPEN-QUESTIONS.md` 的编号

**不得**写"照抄上游某文件"——那违反干净室纪律（宪法原则 II）。
凡为兼容中文排版惯例而写的**非常规**代码（如破折号对的补丁条目），
`basis` 必须注明它相对规范的**偏离方向**与理由，而非假装它是规范原文。

`basis` 为空串（`"   "` 也算空）与缺字段**同等对待**，两者都在解析期被拒。
