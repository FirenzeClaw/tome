# tome · 设计系统 MASTER

> 本文件是 tome 桌面阅读器的**唯一设计规范来源**。所有界面（S2 排版层 / S3 应用外壳）以本文件为准，防止风格漂移。
> 设计输入来源：`demo-studio` 会话（2026-10-10）——用户指定「昼夜双色：亮色=卷轴羊皮暖色，暗色=纯黑基底」。
> 页面类型路由：四页均属**数据型/应用型界面**，遵循 `saas-b-end-ui-spec`（polished / modern / calm / professional）。
>
> **配套文件**：`tokens.css`（本文件的 CSS 变量落地）· `MOTION.md`（动效映射与降级）· `preview.html`（四页原型）· `shots/`（9 张静态归档）。
> **一致性纪律**：`tokens.css` 必须忠实投影本文件的 token；本文件不得出现 `tokens.css` 未定义的 token（反向亦然）。新增/修改 token 时两份同改，否则视为漂移。

## 1 · 设计定位

tome 是**长时间沉浸使用的桌面工具**，不是营销页。设计要服务两件事：

1. **阅读本身**——白天像一卷纸书，夜里像一块 OLED 屏。正文是绝对主角，一切 UI 退到边缘。
2. **书源资产管理**——高密度、需扫读、需批量操作，克制专业而非活泼。

因此采用**昼夜双主题**：
- **昼（Parchment）**：羊皮卷轴暖色。纸面做旧米黄、暖褐墨字、极弱的纸纤维噪点。避免纯白的刺眼，长时间阅读不疲劳。
- **夜（Obsidian）**：OLED 级纯黑基底。真黑背景 + 内容自发光，弱化边框，夜间、暗房、专注场景零干扰。

### 设计 DNA（不可动摇的三条）

| DNA | 说明 |
|---|---|
| **纸与墨** | 昼主题的一切暖色都从「纸」推导（纸面、纸边、折痕、封蜡）；暗主题一切从「墨与光」推导（黑场、微光、荧字） |
| **内容优先** | UI 框架（顶栏/侧栏/面板）永远比正文低一档对比度与一层饱和度；正文区背景始终是最纯净的层 |
| **克制的层次** | 层次靠**间距 + 字重 + 极弱描边**建立，不靠重阴影与强色块 |

- 交互元素 focus 环：2px `--accent-primary` + 2px offset，两主题均保证可见
- 触达目标 ≥ 32px（桌面），图标按钮 ≥ 36px

## 5 · 阅读层规范（响应式排版 · 单双页）

这是 tome 的核心交互，独立成节。

### 5.1 视口与版心

| Token | 值 | 说明 |
|---|---|---|
| `--reading-measure` | `36em` | **单栏理想行长**（约 26–34 个汉字/行），超此宽度不再拉伸版心 |
| `--reading-measure-max` | `42em` | 单栏绝对上限（超过则必须分栏） |
| `--reading-gutter` | `64px` | 双页中缝宽度 |
| `--reading-font-size` | `19px`（可调 14–30） | 阅读字号 |
| `--reading-line-height` | `1.85` | 行高（可调 **1.75–2.2**） |
| `--reading-paragraph-indent` | `2em` | 段首缩进（**默认**） |
| `--reading-paragraph-gap` | `0.4em` | 段间距（与段缩进二选一，用户可切） |

> **行高下限说明**：本表原写「可调 1.4–2.2」，与 §2.3「正文行高 ≥ 1.75（强制）」直接冲突。§2.3 是不等式表达的**无障碍强制条款**，§10 亦把无障碍定为「引擎级强制，非可选皮肤」，故冲突时以下限 **1.75** 为准（裁决 OQ#19→A，spec §FR-013）。

### 5.2 单页 / 双页自动切换规则

**判据不是屏幕宽度，而是「正文版心可用宽度能否容纳两个不小于最小行长的栏」。**

```
available = 阅读区可用宽度
          = 窗口宽度 - 侧栏宽度 - 阅读区左右内边距(2×--sp-10)
singleNeeded = 单栏理想版心 = 36em（em 随阅读字号缩放）
双页启用条件：available >= 2 × singleNeeded + --reading-gutter
```

> **口径声明（重要）**：下表及上式的宽度一律指**阅读区可用宽度**（已扣除侧栏与阅读区内边距），**不是窗口总宽**。原表只写 px 未注明口径，导致与原型算法相差 612px（裁决 OQ#22→A，spec §FR-014）。按窗口总宽理解会在侧栏常驻时过早切双页。

以默认 19px 字号换算（36em = 684px，双页门槛 = 2×684 + 64 = **1432px**）：

| 阅读区可用宽度 | 排布 | 说明 |
|---|---|---|
| `< 640px` | **单页** · 窄版心 | 小窗 / 窄侧栏场景 |
| `640–1431px` | **单页** · 版心居中，最大 36em | 常规窗口——**最舒适单页阅读区** |
| `1432–1671px` | **双页** | 左页/右页并排，中缝 64px |
| `≥ 1672px` | **双页** · 版心加宽 + 可选目录常驻左侧 | 大屏/双屏场景（门槛 = 1432 + 目录栏 240） |

> **上表数值由公式推导，不是独立断点**：`1432 = 2×36em + 64`（19px 时）；`1672 = 1432 + 240`（目录栏宽）。字号变化时二者同步右移。原表写的 `1180 / 1500` 与本文件自己的公式矛盾（按公式应为 `1432 / 1672`），已按公式更正。

**关键行为**：
1. 阈值随**阅读字号**实时重算——用户把字号调到 24px 时，双页阈值相应右移（因为 em 变大）。这通过 `ResizeObserver` + 字号变化的统一 `relayout()` 实现，**不使用固定 px 断点**。
2. 模式切换时**保持阅读位置**不变——用「字符偏移锚点」（spec §FR-027：与排版无关的锚点），切换后滚动到同一字符位置。Demo 中以 `data-anchor` 段落 id 演示。
3. 用户可在工具栏**手动覆盖**为「自动 / 强制单页 / 强制双页」，手动选择在本次会话内优先于自动判定，并按**语义回落**失效：仅当手动选择与当前阅读区可用宽度相矛盾时（如强制双页但宽度已容不下两栏）才回落到自动判定；宽度发生不改变该矛盾的变化时**不清除**用户的手动选择。（原「窗口尺寸变化超过一定幅度时自动接管」的幅度阈值已废弃——它是凭空数字且会误伤微调；裁决 OQ#14→C，spec §FR-015）
4. 双页模式下章节衔接遵循**书页语义**：左页为偶数页、右页为奇数页，章节末尾自动留白补足至偶数页起新章。该行为**可关闭**，开关为设置项「章节从新页开始」——桌面端无「长按」语义，不得以长按手势作为开关。（裁决 OQ#20→C，spec §FR-016）**单页模式下不应用该留白。**

### 5.3 阅读区工具栏

- 默认**隐形**：鼠标静止 2.5s 或鼠标移出阅读区时工具栏淡出（`--dur-base`），只留 8px 顶部热区
- 唤出：鼠标移入顶部热区 / 键盘唤出键（见下）
- 工具栏内容：返回 / 目录 / 进度（章 · 百分比）/ 字号 / 行高 / 主题 / 单双页开关 / 书签 / 换源 / 设置
- **热区为整窗顶部全域**（对齐窗口上沿），**不随单页/双页版心变化**——若热区跟版心走，双页模式下中缝上方会出现热区缺口，鼠标划过时工具栏闪烁。（裁决 OQ#21/I6，spec §FR-034）
- **键位集必须显式成表**（原「`Esc` 之外的任意导航键」是排除法定义，不可验收）。至少覆盖：向前/向后翻页、上/下一章、章首/章末、滚动模式下的行滚动与页滚动、工具栏唤出、以及 `Esc` 的**栈式取消**——阅读区聚焦时 `Esc` 先退出沉浸态/隐藏工具栏；目录或设置以抽屉/弹层形态打开时（栈顶），`Esc` 关闭该层。（裁决 OQ#21→A，spec §FR-035）

> **单页模式下的版心封顶**：本文件 §5.1 的「超过 42em 则必须分栏」与 §5.2 的「手动可强制单页」冲突。裁决（I7）：单页模式下版心**封顶 42em 并居中**，**不自动强制分栏**——显式封顶让两条都不被违反，也避免「我选了单页却被强行分栏」。超出 42em 的部分留白。（spec §FR-014）

## 6 · 响应式自动排布规则（全应用）

窗口任意拉伸时布局必须**连续自适应**，不允许出现固定宽度下的断层：

| 区域 | 自适应策略 |
|---|---|
| **AppShell** | 侧栏宽 `240px` ↔ 折叠 `64px`：容器宽 `< 1024px` 自动折叠为图标栏；`< 768px` 侧栏变为覆盖式抽屉（Overlay），不占据流式宽度 |
| **书架网格** | `grid-template-columns: repeat(auto-fill, minmax(clamp(132px, 11vw, 168px), 1fr))`——列数随宽度连续增减，永不出现半截卡片 |
| **书源/设置表格** | 宽 `≥ 1080px` 全列；`< 1080px` 隐藏次要列（收进行展开）；`< 768px` 转为卡片式列表 |
| **详情/编辑面板** | 宽 `≥ 1280px` 右侧常驻分栏；`< 1280px` 改为抽屉（Drawer）从右侧滑入 |
| **阅读器** | 见 §5.2；侧栏目录在 `≥1672px` 常驻，否则抽屉 |
| **工具栏/操作条** | 空间不足时次要按钮收进「⋯ 更多」溢出菜单，主操作永不隐藏 |
| **弹窗** | 宽 `min(560px, calc(100vw - 48px))`，高度超限内部滚动 |

实现要点：以 **CSS Container Queries + `clamp()` + `auto-fill` 网格** 为主，辅以少量 `ResizeObserver` 驱动的 JS（阅读器模式判定、抽屉态）。**禁止**为每个断点手写一套布局——布局必须是连续的。

## 7 · 组件规范

### AppShell（骨架）

```
┌─────────────────────────────────────────────┐
│ TopBar  56px  品牌 · 全局搜索 · 主题 · 窗口控制 │
├────────┬────────────────────────────────────┤
│ Sidebar │  PageHeader (标题 + 描述 + 主操作)   │
│ 240/64  ├────────────────────────────────────┤
│        │  ContextBar (筛选/分段/面包屑)       │
│  导航   ├────────────────────────────────────┤
│        │                                    │
│        │  Content Area (自适应)              │
│        │                                    │
│        │                                    │
│ 底部:用户│                                    │
└────────┴────────────────────────────────────┘
```

- **TopBar** 56px，不用彩色底，仅 1px 下描边；品牌用 `--font-reading` 衬线（呼应纸书）
- **Sidebar** 用 `--bg-surface`，比 content 低一档；当前项用「左侧 3px `--accent-primary` 竖条 + `--accent-soft` 底」表达，**不用整块实色填充**
- 侧栏底部固定「用户/本地库根目录」区

### 组件清单（四页共用，必做状态）

| 组件 | 要求 |
|---|---|
| `TopBar` | 含全局搜索（`Ctrl+K` 唤起命令面板） |
| `Sidebar` | 展开/折叠/抽屉三态；分组标签 |
| `PageHeader` | 标题 + 一句话描述 + 右侧主操作（唯一 primary） |
| `ContextBar` | 分段控件（Segmented）/ 筛选 chips / 视图切换 |
| `DataTable` | 斑马纹可选、hover 行高亮、列宽自适应、粘性表头、行内 hover 操作 |
| `Card` | 两种：内容卡（书籍）/ 统计卡（数字 + 说明） |
| `BookGrid` | 封面 2:3 比例、悬停浮起 + 阅读进度细线、连载状态徽记 |
| `StatusPill` | 4 态：成功(苔绿) / 警告(鎏金) / 错误(朱红) / 中性(**暖中性灰** `--state-info`) |
| `Button` | primary(封蜡红) / secondary(描边) / ghost(无底) / danger(朱红)；尺寸 sm/base |
| `FormField` | label + 输入 + 帮助文本 + 错误态；focus 环可见 |
| `Switch` | **开关型选项专用**：滑块式，`default / hover / focus-visible / disabled` 四态；开=`--accent-primary` 填充，关=`--bg-inset` 填充 + `--border-strong` 描边；滑块 18px、轨道 36×20px、命中区 ≥32px。**布尔选项不得用复选框或分段控件表达** |
| `Segmented` | 分段控件（视图模式 / 单双页）——**仅用于 2–4 个互斥的枚举值**，不用于布尔开关 |
| `Drawer` | 右侧滑入，含遮罩，`Esc` 关闭 |
| `Modal` | 居中，宽 `min(560px, 100vw-48px)` |
| `Toast` | 右下角，4 态，4s 自动消失 |
| `EmptyState` | 插画位 + 标题 + 说明 + 主操作（禁止只有一行灰字） |
| `LoadingSkeleton` | 骨架屏，微光扫过（`prefers-reduced-motion` 降级为静态） |
| `ErrorState` | 错误图标 + 原因 + 重试按钮 |
| `ProgressBar` | 细线式，`--accent-clash` 高光 |
| `CommandPalette` | `Ctrl+K` 唤起，居中弹层；模糊搜索 + 分组结果 + 键盘上下选择 + `Esc` 关闭 |

### 交互状态（强制）

所有可交互元素必须实现：`default / hover / focus-visible / active / disabled`，其中 `focus-visible` 必须是**真实可见的环**，不得用 `outline:none` 抹掉。

### 设置型页面的交互契约（**改完即存**）

设置页**不设「保存」按钮**。原因：桌面设置页的「保存/取消」会让用户产生「我的修改还没生效」的不确定感，而设置项本身都是低风险、可单步撤销的。

| 规则 | 说明 |
|---|---|
| **即时生效** | 控件值变更即刻写入配置，无需确认 |
| **单一 primary 的替代** | 设置页因此**不强制**「唯一 primary action」——该页自然的 primary 是「任何一次编辑」。（§9 的「有且仅有一个清晰 primary action」对设置页按此条款解释） |
| **保存中** | 显示轻量状态（`保存中…`），不得阻塞交互 |
| **保存成功** | 短暂提示后自动消失（复用 `Toast`，成功后 2s） |
| **保存失败** | **必须显式报错**：该项旁显示 `ErrorState` 内联样式（图标 + 原因 + 「重试」），并给出 `Toast`；**不得静默失败**，也不得回滚用户输入而不说明 |
| **回滚语义** | 失败时保留用户的输入值并标记为「未保存」，而非静默还原——用户重试时不必重新输入 |
| **危险项** | 仅「删除库根目录」这类破坏性操作用 `Modal` 二次确认，其余一律即时生效 |

> **与 spec 的关系**：设置页面的布局归 S3；本条款约束的是**交互契约**（何时落盘、失败怎么表达），S2/S3 均须遵守。`Switch` 的存在是因为原稿把布尔项画成了分段控件，语义不准。

## 8 · Do's & Don'ts

### Do
- ✅ 正文用衬线、UI 用无衬线、规则用等宽——三角色字体各司其职
- ✅ 用间距与字重建层次，用极弱描边勾形
- ✅ 图表/进度用鎏金点缀，成功用苔绿，警示用朱红——所有语义色都从暖色系推导
- ✅ 阅读区永远是屏幕上最安静的地方
- ✅ 每个列表/表格都有空/载/错三态
- ✅ 主题切换用 280ms 全站渐变过渡，像晨昏交替

### Don't
- ❌ 禁止蓝色系（通用 admin 蓝）——本项目暖色系身份不可妥协
- ❌ 禁止纯白 `#FFFFFF` 作昼主题底（刺眼）——用做旧羊皮色
- ❌ 禁止夜主题用深灰代替真黑（OLED 价值丢失）
- ❌ 禁止卡片堆叠无层级、禁止重阴影、禁止 >700 字重
- ❌ 禁止固定 px 断点堆砌响应式——布局必须连续
- ❌ 禁止阅读区出现装饰性图形、广告位、鲜艳色块
- ❌ 禁止把功能标注（[WIP] 等）写进用户可见 UI

## 9 · 页面验收标准

每个界面必须满足（对齐 `saas-b-end-ui-spec`）：

- [ ] 首屏信息 scent 明确：一眼知道「我在哪、能做什么、下一步」
- [ ] 有且仅有一个清晰 primary action（**设置页除外**：该页「改完即存」，见 §7 设置型页面交互契约）
- [ ] 表格/列表可快速扫读，关键状态视觉化
- [ ] 空数据 / 加载中 / 错误三态完整
- [ ] 布尔选项用 `Switch`，枚举选项用 `Segmented`——不得混用
- [ ] 设置项保存失败时有可见的错误提示与重试入口（不得静默失败）
- [ ] 键盘可操作，`focus-visible` 可见
- [ ] **1440 / 1280 / 1024 / 768 四档宽度下布局不崩**（本设计扩展至 1920 与 640）
- [ ] 昼/夜双主题下均通过对比度与可读性检查
- [ ] 阅读器：**单页/双页切换在阈值处正确触发且阅读位置不丢**
- [ ] 控制台无错误；无 `style` 内联硬编码色值（除数据驱动）

## 10 · 技术落地映射

| 本规范 | Rust 桌面实现落点（S2/S3） |
|---|---|
| 色彩/间距/字号 tokens | 单一 `theme` 模块产出 `Theme` 结构体，昼/夜两实例；禁止各控件散读常量 |
| 字体族 | 打包内嵌字体（衬线正文 + 无衬线 UI + 等宽），确保三平台一致；注意 <20MB 体积预算 |
| 响应式排布 | 布局引擎用「容器宽度 → 列数/分栏」的连续函数，不用断点表 |
| 单双页切换 | 以 `measure` 计算而非窗口宽度；字号/行高变化触发重排并复原字符锚点 |
| 动效 | 统一 `Duration`/`Easing` 常量；`prefers-reduced-motion` 对等开关 |
| 无障碍 | 焦点环、键盘导航、对比度为引擎级强制，非可选皮肤 |
