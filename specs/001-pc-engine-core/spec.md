## User Scenarios & Testing *(mandatory)*

> 说明：S1 交付物是**无界面的引擎内核（可被上层调用的库）+ 命令行验证器**。因此下文的"用户"包含两类：**最终读者**（通过后续 S2/S3 子项目获得完整体验，但其体验依赖 S1 定义的行为）与**下游构建者**（阅读器与界面层的开发者，依赖 S1 的接口契约）。

### User Story 1 - 用书源搜索并阅读一本书 (Priority: P1)

一位读者手上有若干份社区流通的书源文件。他把书源导入后，输入书名关键词，看到来自多个书源的搜索结果；他从结果中选一本加入书架，打开后看到章节目录，点击任一章节即读到该章正文。

**Why this priority**: 这是整个产品存在的理由，也是引擎全部子系统的唯一端到端汇合点——规则解析、脚本执行、网络抓取、字符处理、内容加工、存储写入全部必须协同工作才有价值。只实现这一条，就已经具备可验证的 MVP。

**Independent Test**: 提供一份书源与一个关键词，通过命令行验证器执行「搜索 → 详情 → 目录 → 正文」并获得结构化文本输出；不需要任何图形界面，也不需要后续子项目。

**Acceptance Scenarios**:

1. **Given** 一份有效书源与网络可用，**When** 用户以关键词触发搜索，**Then** 系统返回包含书名、作者、来源标识的候选结果列表
2. **Given** 一条搜索结果，**When** 用户请求书籍详情，**Then** 系统返回简介、封面地址、目录地址等可用信息
3. **Given** 一本已选定的书，**When** 用户请求目录，**Then** 系统返回有序的章节列表
4. **Given** 目录中的任一章节，**When** 用户请求正文，**Then** 系统返回该章纯文本正文，且已应用用户配置的净化规则
5. **Given** 一次已完成的阅读，**When** 用户重新打开该书，**Then** 系统恢复到上次离开的章节与位置

---

### User Story 2 - 既有书源无需改动即可使用 (Priority: P2)

读者从社区获得的书源（通常为一份 JSON 定义，内含 HTML/JSON 选择规则与脚本片段）能够直接工作，不需要作者为桌面版重写或适配。

**Why this priority**: 书源生态是这个项目不可替代的资产。若既有书源无法直接使用，产品价值将退化为"又一个本地阅读器"。优先级仅次于端到端链路，因为它决定这条链路能覆盖多少真实内容。

**Independent Test**: 取一批真实书源，对每一份执行相同输入，将引擎输出与参考行为逐项比对，统计一致率；可脱离界面独立运行。

**Acceptance Scenarios**:

1. **Given** 一份使用选择器规则的书源，**When** 执行抓取，**Then** 输出与参考行为一致
2. **Given** 一份在规则中嵌入脚本的书源，**When** 执行抓取，**Then** 脚本被正确执行且结果与参考行为一致
3. **Given** 一份使用了系统不支持能力的书源（如依赖内嵌浏览器），**When** 执行抓取，**Then** 系统明确报告"该能力不受支持"及受影响的具体动作，而非静默失败或崩溃
4. **Given** 一份会长时间占用或内存失控的书源，**When** 执行抓取，**Then** 系统在限定资源内终止该源并保持整体可用

### User Story 3 - 阅读本地书籍 (Priority: P3)

读者把自己电脑上的 TXT、EPUB、MOBI/AZW3 文件加入书架并阅读，也可以指定若干本地目录让应用扫描。

**Why this priority**: 本地阅读是阅读器的基本盘，且不依赖网络，是网络书源失效时的可靠退路。但它不是本项目的差异化价值（任何阅读器都能读本地文件），故排在兼容性之后。

**Independent Test**: 给定三类格式的样本文件，执行导入与章节提取，检查目录与正文的完整性与正确性。

**Acceptance Scenarios**:

1. **Given** 一个 TXT 文件，**When** 用户导入，**Then** 系统识别编码、识别出章节目录并可按章定位
2. **Given** 一个 EPUB 文件，**When** 用户导入，**Then** 系统解析出书名、作者、目录与正文
3. **Given** 一个 MOBI/AZW3 文件，**When** 用户导入，**Then** 系统解析出目录与正文
4. **Given** 用户指定的本地目录，**When** 用户触发扫描，**Then** 系统列出可用书籍而不移动或改写原文件
5. **Given** 已索引的本地书，**When** 用户移动整个目录或更换盘符后重新扫描，**Then** 索引被正确重建且不产生重复书目

---

### User Story 4 - 阅读数据可靠保存且可迁移 (Priority: P4)

读者的书架、阅读进度、书签、高亮、批注与书源资产被可靠保存；程序异常退出或断电后数据不损坏；数据目录可随程序一起搬移。

**Why this priority**: 数据丢失是阅读类应用最不可接受的失败。它独立于内容获取——即使所有书源都失效，用户的历史资产也不能丢。同时"可移植"是桌面用户区别于移动端的核心预期。

**Independent Test**: 在写入过程中强制中断进程，重启后校验数据完整性与可读性；将数据目录整体移动到另一路径后启动，校验状态一致。

**Acceptance Scenarios**:

1. **Given** 正在写入缓存或进度，**When** 进程被强制终止，**Then** 重启后数据可读、无指向不存在内容的引用
2. **Given** 已建立的数据目录，**When** 整体移动到另一个路径，**Then** 应用在该新位置正常工作且状态不变
3. **Given** 一份来自既有 Android 版本的备份文件中的书源，**When** 用户导入，**Then** 书源被正确识别并可用
4. **Given** 用户希望清理空间，**When** 触发缓存清理，**Then** 缓存被释放且阅读进度、书签等个人数据不受影响

---

### User Story 5 - 正文按用户规则加工 (Priority: P5)

读者配置的净化/替换规则、高亮规则与词典规则在阅读时生效：广告与无关文本被去除，指定内容被高亮标记，选中词语能查到释义。

**Why this priority**: 这是从"能读"到"读得舒服"的跃迁，也是重度用户长期积累的个性化资产。但它建立在内容已能获取之上，故排在其后。

**Independent Test**: 给定固定正文与一组规则，检查加工后的文本与匹配区间是否符合规则定义。

**Acceptance Scenarios**:

1. **Given** 一条替换规则，**When** 正文被加工，**Then** 匹配内容按规则被替换，且多条规则按定义顺序依次生效
2. **Given** 一条高亮规则，**When** 正文被加工，**Then** 系统产出待标注的字符区间（区间语义与排版无关）
3. **Given** 一个选中词，**When** 触发查词，**Then** 系统返回该词对应的释义结果
4. **Given** 加工规则包含错误，**When** 正文被加工，**Then** 该规则被跳过并记录原因，其余规则与正文仍正常输出

---

### User Story 6 - 作为上层可依赖的稳定接口 (Priority: P6)

阅读器与界面层的开发者通过一组固定的接口获得内容与数据，不需要了解抓取、解析、存储的内部细节；并且能用一个命令行工具在不启动界面的情况下验证行为。

**Why this priority**: 它直接决定 S2/S3/S4 三个后续子项目能否独立推进。放在最后是因为它服务于其他故事，而非独立用户价值——但它是架构能否成立的关键约束。

**Independent Test**: 在无图形环境（无窗口系统）下调用引擎完成一次完整抓取与数据读写；检查引擎被替换实现时上层无需改动。

**Acceptance Scenarios**:

1. **Given** 一个无图形环境的系统，**When** 引擎被调用，**Then** 全部功能可用且不出现图形相关依赖错误
2. **Given** 命令行工具与一份书源，**When** 执行各抓取动作，**Then** 输出结构化结果可供自动比对
3. **Given** 引擎的内部实现被替换（如更换存储或网络实现），**When** 上层调用不变，**Then** 上层无需修改

### Edge Cases

- **书源返回空结果**：搜索无匹配、目录为空、正文为空时，系统必须区分"源正常但无数据"与"源失效"，并给出可操作提示
- **书源被限流或封禁**：连续请求触发限流时，系统应遵循书源声明的间隔并在必要时降速，而不是重试到被封
- **网络中途断开**：正在进行的抓取应可恢复或明确失败，不得留下半写入的数据
- **响应编码异常**：响应头声明与实际编码不符、或包含非法字节时，仍需产出可读文本
- **超长章节**：单章正文达数十万字时，缓存与加工流程不得因单章过大而失败
- **超短章节**：单章仅数百字时，缓存组织不得产生大量碎片
- **书源数量庞大**：同时启用数百个书源时，搜索须保持可取消且不耗尽资源
- **脚本死循环或内存膨胀**：单个脚本失控必须被终止，且不影响其他书源与进程本身
- **脚本抛出自定义错误**：书源自身的错误处理逻辑（捕获并降级）必须能正常工作
- **本地书格式损坏**：损坏的 EPUB/MOBI 应报错并跳过，不阻塞其他书的导入
- **TXT 无目录结构**：无法识别章节的文件应作为单章或按大小切分，而非导入失败
- **磁盘空间不足**：写入失败时须明确报告，且不得破坏既有数据
- **数据目录不可写**：须在启动时检测并给出明确指引，而非运行中途静默失败
- **多个本地库目录指向同一文件**：应识别为同一本书，不重复出现在书架
- **书源规则本身有语法错误**：须定位到具体动作与字段并报告，其余书源不受影响
- **重复导入同一书源**：再次导入已存在的书源须被识别为同一份并按确定策略处理（更新或跳过），不得产生重复条目
- **脚本试图写入数据目录以外的位置**：须拒绝并明确报告，不得静默写入任意路径
- **代理不可用或代理认证失败**：须明确区分"代理故障"与"目标站点故障"，并允许用户为单个源关闭代理
- **图片无法获取或返回非图片内容**：须回退到占位而非展示损坏内容，且不中断正文获取

## 范围与阶段 *(mandatory)*

本轮规格覆盖 **S0** 与 **S1**。后续 S2（排版与渲染）、S3（应用外壳）、S4（订阅/朗读/词典/定时任务）各自独立规格，不在本轮范围。

### S0 — 技术可行性验证（前置）

目的是在投入大规模实现前，用最小成本确认技术路线在三平台可行并取得体积与性能的实测基线。

**S0 的交付物**：一个最小可运行程序，具备显示窗口、读写本地结构化数据、发起一次网络请求、执行一段脚本的能力；在三个目标平台上分别构建出产物，并记录产物体积与启动耗时。

**S0 的验收**：三平台均产出可运行产物；记录体积与启动耗时作为基线数据；不出现任何未经用户动作触发的网络外发。

**S0 与 S1 的关系**：S0 是**基线采集与可行性确认**，不是硬性阻塞闸门。体积实测结果不构成通过/失败判据（体积为目标基线而非门槛），但若三平台无法构建或无法运行，须在进入 S1 前重新评估技术选型。若 S1 的接口契约可先行确定，S0 与 S1 的接口设计可并行推进。

### S1 — 引擎内核（本轮主体）

**在范围内**：书源导入与解析（含文件/URL/粘贴文本三种渠道）、规则求值与脚本执行、网络抓取与内容管线（含代理与限速）、多源并行搜索与发现、换源与源可用性检查、换源进度映射（特征段→标题→降级）、正文净化与高亮/词典规则求值、封面与正文图片获取及缓存、书内全文搜索（已缓存章节）、本地书解析与库根扫描、持久化（书架/进度/书签/高亮/批注/阅读记录/规则配置/请求日志/Cookie）、章节缓存、原子化配置读写、数据可移植、备份中的书源导入、全部阅读数据的导入导出、无界面库接口、命令行验证器（含规则求值轨迹）、可本地化错误标识、三平台构建。

**明确排除**（本轮不做，且不预留实现）：
- 依赖内嵌浏览器的书源能力（须以结构化错误明确报告，不得视为缺陷）
- PDF、UMD 格式；压缩包（zip/rar/7z）扫描导入
- 竖排排版（本轮无排版层，天然不含；S2 的范围由 S2 规格自行确定）
- 界面、排版、渲染、翻页动效（S2/S3）
- 订阅（RSS）阅读、朗读（TTS）、词典查询界面、定时任务调度（S4）
- 音频播放、漫画、视频（S4 且默认不启用）
- 编程接口服务（HTTP/WebSocket/MCP）：v1 无消费方，不做
- 应用自身自动升级、跨设备同步、WebDAV 与局域网传输
- 遥测、崩溃上报、任何形式的使用数据外发
- 书源变更追踪（上游 BookSourceChange 的字段级变更历史）——低频低价值，本期不做

## Requirements *(mandatory)*

### Functional Requirements

#### 书源与规则

- **FR-001**: 系统 MUST 支持导入符合既有社区流通格式的书源定义（单个与批量），导入渠道 MUST 至少覆盖三种：**本地文件**（选择或拖入）、**URL**（粘贴链接后拉取并解析）、**粘贴文本**（直接粘贴书源 JSON 文本）。系统 MUST 支持书源的分组与启停
- **FR-002**: 系统 MUST 支持书源的五类抓取动作：搜索、发现（分类遍历）、书籍详情、目录、正文
- **FR-003**: 系统 MUST 支持书源规则中使用的选择语法，包括结构选择（网页标记与结构化数据）、路径选择、正则匹配、脚本表达式，以及它们之间的组合运算
- **FR-004**: 系统 MUST 支持规则结果的后处理链：按正则的查找替换（可叠加）与内嵌表达式的求值
- **FR-005**: 系统 MUST 支持在规则中调用脚本，并提供与既有生态一致的能力集。该能力集 MUST 逐项可枚举、可验证，至少覆盖以下类别：
  - **网络**：单次请求、并发批量请求、下载到缓存、下载到文件
  - **文本与编码**：Base64、URL 编解码、十六进制、字符集转换、中文简繁转换
  - **摘要与加密**：MD5/SHA 系列摘要、AES/DES/RSA 加解密与签名
  - **结构化数据**：JSON/XML 的解析与路径取值、网页标记的解析与选择
  - **正则**：匹配、查找、替换、捕获组提取
  - **时间日期**：时间戳与格式化字符串互转、日期计算
  - **杂项**：随机数、压缩与解压、HTML 实体处理
  - **宿主状态**：缓存读写、文件读写（限于数据目录内）、Cookie 读写、引入外部脚本、变量池读写、当前书源/书籍/章节上下文访问
- **FR-005b**: 该能力集 MUST 有一份显式的、可被测试逐项覆盖的清单，作为一致性验证用例集的覆盖矩阵（见 FR-038）
- **FR-006**: 当书源使用系统不支持的能力时，系统 MUST 抛出可被书源自身错误处理捕获的结构化错误，错误须携带能力标识与人类可读说明
- **FR-007**: 系统 MUST 对脚本执行施加资源约束（内存上限与可中断），单个失控脚本 MUST NOT 导致进程崩溃、无响应或影响其他书源
- **FR-008**: 系统 MUST 支持书源声明的请求定制：方法、请求头、请求体、编码、Cookie、超时、重试与请求间隔；并 MUST 支持代理配置（跟随系统代理，以及按源单独指定代理）
- **FR-009**: 系统 MUST 正确处理响应的字符集（含声明与实际不符、以及非 UTF-8 内容）与压缩传输
- **FR-010**: 系统 MUST 支持"换源"：给定一本书，跨源检索候选并获取其目录与正文
- **FR-010b**: 换源后系统 MUST 尽量保留阅读进度，按以下顺序降级匹配定位到新源位置：
  1. **特征段匹配**：取当前页正文的特征片段，在新源大致位置的邻域章节缓存内搜索匹配；采用约 90% 的相似度阈值以容忍部分书源的错字/漏字；命中则定位到该处
  2. **章节标题匹配**：特征段未命中时，按章节标题近似匹配定位到对应章节
  3. **降级兜底**：均未命中时，明确提示用户进度无法自动映射并落到目录开头，不静默跳转
  换源过程 MUST 可观测（告知用户采用了哪一级匹配及其结果）
- **FR-011**: 系统 MUST 支持书源可用性检查（单源与批量），并给出可判定的结论

#### 内容获取与加工

- **FR-012**: 系统 MUST 支持多源并行搜索，单源失败或超时 MUST NOT 影响其他源；结果须增量呈现且整体可取消
- **FR-013**: 系统 MUST 支持发现（分类浏览）的导航与分页
- **FR-014**: 系统 MUST 支持用户配置的正文净化/替换规则，按定义顺序应用；内容加工链的顺序 MUST 确定为：替换规则 → 高亮规则求值 → 词典规则求值，且该顺序对所有消费者一致
- **FR-015**: 系统 MUST 支持高亮规则求值，产出与排版无关的字符区间
- **FR-016**: 系统 MUST 支持词典规则求值，给定词语产出释义结果
- **FR-017**: 系统 MUST 支持可开关的请求/响应日志记录，供用户排查书源问题；日志须可清理且不无限增长
- **FR-018**: 系统 MUST 支持搜索关键词的管理（收藏与复用）
- **FR-019**: 系统 MUST 支持获取并缓存书籍封面与正文内嵌图片（含来源鉴权头、失败重试与占位处理），供上层展示；图片缓存 MUST 可独立清理
- **FR-019b**: 系统 MUST 支持书内全文搜索：对一本书的已缓存章节内容进行全文检索，返回命中的章节与位置（供上层实现"书内 Ctrl+F"）；检索 MUST 限定在已缓存内容，不触发额外抓取

#### 本地书籍

- **FR-020**: 系统 MUST 支持 TXT 导入：识别编码、识别章节目录（支持多条规则回退）、按位置定位章节
- **FR-021**: 系统 MUST 支持 EPUB 导入：解析书名、作者、目录、正文与内嵌资源
- **FR-022**: 系统 MUST 支持 MOBI/AZW3 导入：解析目录与正文并归一化，使其可被随机定位
- **FR-023**: 系统 MUST 支持添加多个本地库目录，只索引不移动或改写原文件
- **FR-024**: 系统 MUST 支持在导入时可选地复制文件到库目录（非强制行为）
- **FR-025**: 系统 MUST 在文件移动或库目录路径变化后正确重建索引，且不产生重复条目

#### 存储与数据

- **FR-026**: 系统 MUST 持久化书架、阅读进度、书签、高亮、批注、书源、规则配置、请求日志与 **Cookie**（按源落盘，重启后保留登录态）
- **FR-026b**: 系统 MUST 在数据层记录阅读记录（每本书的阅读时长与阅读字数，可聚合为日/总量统计），数据层的记录行为 MUST 不依赖任何界面（无界面下同样落库）；本期不出统计界面
- **FR-027**: 系统 MUST 以与排版无关的锚点保存阅读进度（章节标识 + 文本位置），使字号或窗口尺寸变化后仍能回到原处
- **FR-028**: 系统 MUST NOT 以渲染坐标存储任何阅读痕迹（高亮/批注/书签）
- **FR-029**: 系统 MUST 将网络书的章节内容以批量容器形式缓存，容器容量可配置
- **FR-030**: 系统 MUST 保证缓存写入的崩溃安全：异常中断后重启 MUST NOT 出现指向不存在内容的引用
- **FR-031**: 系统 MUST 支持以容器为单位的缓存淘汰，淘汰后不产生残留引用；缓存清除 MUST NOT 影响个人阅读数据
- **FR-032**: 系统 MUST 将应用级设置保存为可读、可手工编辑、可随程序搬移的配置，且写入具备原子性
- **FR-033**: 系统 MUST 支持导出与导入**全部阅读数据**：书源集合、书架清单、阅读进度、书签、高亮、批注、规则配置（净化/高亮/词典），格式为可读的 JSON；导出与导入须对称（能导出即可完整导回）
- **FR-034**: 系统 MUST 支持从既有 Android 版本应用产生的备份中导入书源
- **FR-035**: 系统 MUST 支持完整删除用户数据（配置、缓存与个人数据）

#### 接口与可测性

- **FR-036**: 系统 MUST 以无界面库的形式提供全部引擎能力，且 MUST NOT 依赖任何窗口或图形环境
- **FR-037**: 系统 MUST 提供命令行工具，可对给定书源执行各抓取动作并输出结构化结果；MUST 支持可选的**规则求值轨迹**输出（逐步展示每一步规则匹配到的中间值），供上层实现书源调试器
- **FR-038**: 系统 MUST 提供一致性验证能力：对同一输入，引擎输出可与参考行为逐项比对并统计一致率
- **FR-039**: 引擎 MUST NOT 依赖阅读器或界面层的任何类型；上层实现被替换时引擎无需改动

#### 平台与合规

- **FR-040**: 系统 MUST 可在三个目标平台构建并运行：Windows 10 及以上、macOS 12 及以上、主流现代 Linux 发行版
- **FR-041**: 系统 MUST NOT 包含遥测或崩溃上报；除用户明确触发的书源抓取外，MUST NOT 产生任何网络外发
- **FR-042**: 系统 MUST 支持可移植运行：数据目录可置于程序同级并随程序整体移动
- **FR-043**: 系统 MUST 在数据目录不可写或磁盘空间不足时明确报告并给出指引，而非静默失败
- **FR-044**: 系统 MUST 支持中英双语界面所需的文案切换能力（引擎侧产出可本地化的错误与提示标识；界面文案由上层承接）

### Key Entities

- **书源（Source）**: 一份内容抓取定义。包含标识、名称、分组、启用状态、地址、五类动作的规则定义、请求定制（头/Cookie/间隔）、以及可选的脚本体。存在多种形态（网页规则源、结构化数据源、纯脚本源），以统一标识区分
- **书源分组（Source Group）**: 书源的归类，用于组织与批量启停
- **书籍（Book）**: 书架条目。包含书名、作者、封面、简介、来源标识、来源类型（网络/本地）、分类标签、书架分组、以及该书生效的排版偏好
- **章节（Chapter）**: 属于某本书的章条目。包含序号、标题、地址或本地位置、是否已缓存、已读状态
- **章节缓存容器（Chapter Cache Pack）**: 网络书章节内容的落盘单元，聚合多章以减少文件数量；记录所辖章节与内容区间
- **阅读进度（Read Progress）**: 某本书的当前位置，以与排版无关的锚点表示
- **阅读记录（Read Record）**: 某本书的累计阅读时长与阅读字数，可聚合为日/总量统计；数据层记录，本期不出界面
- **书签（Bookmark）**: 用户在特定位置标记的记录，含备注
- **高亮（Highlight）**: 用户或规则在文本中标记的字符区间，含样式标识与备注
- **批注（Memo）**: 对文本区间的个人笔记
- **替换/净化规则（Replace Rule）**: 文本加工规则，含匹配定义与替换内容、生效范围
- **高亮规则（Highlight Rule）**: 自动识别待高亮区间的规则
- **词典规则（Dict Rule）**: 查词时使用的释义来源定义
- **目录识别规则（TOC Rule）**: 用于识别本地 TXT 章节目录的规则
- **搜索关键词（Search Keyword）**: 用户收藏的检索词
- **请求日志（HTTP Log）**: 一次抓取的请求与响应记录，用于排查
- **Cookie**: 按源存储的登录态数据，持久化落盘，重启后保留；敏感数据，日志中须脱敏
- **图片缓存（Image Cache）**: 书籍封面与正文内嵌图片的本地副本，按来源与地址索引，可独立清理
- **库根目录（Library Root）**: 一个被索引的本地目录，书籍以"目录标识 + 相对路径"关联，故移动目录树不影响索引
- **应用配置（App Config）**: 应用级设置（网络、代理、缓存上限、界面语言、行为偏好）
- **错误标识（Error Kind）**: 引擎产出的可本地化错误分类（网络/规则/不支持能力/内容），供上层映射为面向用户的文案

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用一份有效书源，读者从输入关键词到看到至少一个来源的搜索结果，耗时不超过 30 秒（正常网络条件）
- **SC-002a**: 规则语义一致性（合成用例档）：针对各语法点构造的合成用例集，通过率不低于 95%
- **SC-002b**: 规则语义一致性（真实书源档）：真实书源端到端抓取的结果一致性作为持续回归指标，不设硬门槛，首轮基线记录在案并在后续迭代中不得回退
- **SC-003**: 引擎加载一本 5 万章的网络书目录（从请求发起到返回可用结果），耗时不超过 1 秒
- **SC-004**: 导入 100 MB 的单文件 TXT 并完成目录识别，耗时不超过 8 秒（典型规模）；300 MB 作为**上限参考**，在此规模下不得失败或耗尽资源，耗时不作硬性要求
- **SC-005**: 章节缓存的存储开销可量化且受控：缓存目录总字节数 ≤ 所缓存正文内容字节数 × 1.01（差额为容器分片填充与索引开销）。尚未填满的容器按实际占用计入；该比值在任何缓存规模下均成立
- **SC-005b**: 5 万章规模下，单章平均 6 KB 的书籍，其缓存文件数量不超过总章数的 2%（即批量容器确实降低了文件数量）
- **SC-006**: 多源搜索中任一源失败或超时时，其余源的结果 100% 照常返回且无需用户重试
- **SC-007**: 在写入过程中强制终止进程后重启，数据 100% 可读且不存在指向缺失内容的引用
- **SC-008**: 阅读进度锚点与排版参数无关：同一位置在任意排版参数组合下解析为同一锚点值，且回读后指向同一处文本（100%）。该不变性在无界面环境下以参数化方式验证，无需真实改变窗口尺寸
- **SC-009**: S1 的库与命令行产物在三个目标平台的体积基线被记录在案（不设上限判据）；最终桌面应用 "<20 MB" 的目标基线由 S3 规格承接，S1 只需保证不引入与功能无关的体积膨胀（如未使用的静态依赖）
- **SC-010**: 三个目标平台均能构建并产出可运行产物（100%）
- **SC-011**: 在无图形环境的系统上，全部引擎能力可被调用且无图形相关失败（100%）
- **SC-012**: 运行期间不存在任何非用户动作触发的网络外发（100%）
- **SC-013**: 单个失控脚本（死循环或内存膨胀）被终止后，进程与其余书源功能 100% 保持可用
- **SC-014**: 图片与封面获取失败时，正文获取成功率不受影响（100% 不因图片失败而中断）
- **SC-015**: 用户执行缓存清理后，个人阅读数据（书架/进度/书签/高亮/批注/书源/规则）100% 保留
- **SC-016**: 引擎产出的全部面向用户的错误均可映射为中英文案，不存在只在单一语言下可读的错误输出（100%）
- **SC-017**: 章节缓存与图片缓存是两个可独立清理的资源：清理其一不影响其二的可用性，两个清理入口在接口上可分别调用（100%）
- **SC-018**: 需鉴权的图片（依赖来源站点的请求头或 Cookie）能够成功获取的比例，与正文获取成功率一致（100%）

## Assumptions

### 已批准的技术约束（来自设计共识，供规划阶段承接）

以下选型已由用户在设计共识阶段明确批准，作为规划阶段的输入，避免重复决策。它们不在功能需求中复述。

- 实现路线为**单体原生桌面应用**，引擎与界面同进程；不做 Web 前端 + 内嵌浏览器外壳方案
- 三条平台线一致：Windows 10+、macOS 12+、现代 Linux；不使用依赖系统运行时的跨平台框架
- 优先级次序为 **兼容性 > 性能 ≈ 视效与体验完整性**；体积 <20MB 为**目标基线而非硬门槛**，必要时可超出并记录原因
- **干净室纪律**：本仓库为独立全新仓库，许可证为 MIT/Apache-2.0。不得阅读或逐行移植上游 Kotlin 实现；上游代码仅可作为**黑盒参考**（运行以产生对照输出）与**行为存在性证据**（据此构造测试用例），语义须依据书源原始规则与公开文档独立推导
- 一致性验证通过**差分测试**实现：以参考实现产出的输入→输出对照数据为基准，比对引擎输出
- 章节缓存采用**容器（多章一文件）**组织，容器按累计内容大小与章节数滚动生成；因网络书章节可能按需乱序获取，容器归属按**写入顺序**而非章节序号分配；索引记录于结构化存储，内容追加落盘先于索引提交，以保证崩溃安全
- 应用级设置使用**可手工编辑的文本配置**（TOML），采用原子写入；书籍级数据存于结构化存储；主题作为独立可分享文件
- 阅读痕迹一律以**字符区间**表达，不使用渲染坐标
- 数据目录支持**可移植模式**（置于程序同级）
- 网络层使用 `reqwest`（保留 HTTP/2）与 `rustls` + 系统信任库；脚本侧网络调用使用同步阻塞客户端以满足脚本的同步语义
- 脚本运行时采用 QuickJS（`rquickjs`，支持内存上限与执行中断）；对上游脚本方言差异以**兼容前导脚本**补齐
- 排版与渲染层（S2）将使用 cosmic-text 做字形整形、自研中文排版规则、wgpu 渲染、纹理化翻页动效；阅读页不经过即时模式 UI 框架的文本栈——以上属 S2 规格范围，此处仅记录以避免与 S1 冲突
- 不捆绑任何字体；依赖系统字体并在缺失时给出明确指引
- 中英双语界面为交付目标（S3 范围），文案组织按功能模块推进而非一次性全量
- 构建与发布使用三平台持续集成；产物体积进入持续集成监控

### 其他假设

- **目标用户为单机单用户**：不涉及多用户账号、权限与协作；并发规模远低于服务端场景
- **书源为第三方资产**：本产品不内置任何书源；用户自行导入。验证用真实书源在本机执行，不纳入仓库
- **验证语料构成**：可入仓库的部分为针对各语法点手工构造的合成用例；真实书源端到端对照在本机或受控环境执行
- **不涉及 DRM**：受加密保护的电子书无法解析，系统须明确报错
- **用户具备网络连接**：网络书源功能的前提；离线时本地书功能须完整可用
- **不提供内容**：本产品只提供抓取与阅读工具，不托管、不存储、不分发任何第三方内容
- **上游行为为移植基准**：当上游行为本身存在缺陷时，以兼容性优先，除非该行为导致数据损坏或安全问题
- **TLS 指纹差异属已知限制**：更换网络栈会改变传输层特征，少数做指纹识别的书源可能失效；该限制记录在案，其增强方案（如特定传输栈）归入后期增强项，不在本轮承诺内
- **体积预算的取舍顺序已定**：体积为目标基线而非硬门槛。S1 的关注点是"不引入与功能无关的体积膨胀"（例如未被使用的静态依赖、重复的解析器实现）。渲染后端已在设计共识中定案、不再作为体积降级项；若 S0 或 S3 阶段发现体积显著超出目标，**由用户重新裁决**取舍方向，而非沿预设顺序自动降级
- **本轮不交付用户可直接使用的应用**：S1 的产出是库与命令行工具；完整体验依赖 S2/S3
- **依赖第三方服务的可用性不由本产品保证**：书源失效、目标站点改版属外部变化，系统只负责如实报告
